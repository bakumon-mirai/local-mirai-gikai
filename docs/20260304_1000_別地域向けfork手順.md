# 別地域向け Fork 手順書

> このガイドは、地方議会版ベーステンプレート（[bakumon-mirai/local-mirai-gikai](https://github.com/bakumon-mirai/local-mirai-gikai) の `main` ブランチ）を
> 特定の地方議会向けに fork する際の手順をまとめたものです。
> 川崎市議会版（2026-02）・神奈川県議会版（2026-03）・福岡市議会版の経験を反映しています。

## 0-0-0. 準備：テンプレートを手元に置く

> [!IMPORTANT]
> **fork する前に、[0-0 の調査](#0-0-その前にその自治体で何が作れるか調べる)と、
> 同じ自治体の既存の版の確認・着手の判断（council-survey Step 5.5）を済ませてください。**
> 調査は fork しなくても、調査手順書
> （https://raw.githubusercontent.com/bakumon-mirai/local-mirai-gikai/main/.claude/skills/council-survey/SKILL.md ）
> を AI エージェントに読ませれば実行できます。

以降の手順は、**テンプレート（`main`）を fork して clone した作業ディレクトリがある前提**で書かれています。
まだ無い場合は、先にこれを用意してください。

> [!IMPORTANT]
> **clone ではなく、GitHub 上で fork してから clone してください。**
> テンプレートは本家 [team-mirai/mirai-gikai](https://github.com/team-mirai/mirai-gikai) の
> fork ネットワークに属しています。clone して別リポジトリに push すると繋がりが切れ、
> **後から張り直すことはできません**。手順の詳細と、fork 済みアカウントの場合の回避策は
> [README の「リポジトリを用意する」](../README.md#リポジトリを用意する) を参照。

```bash
# fork 済みの自分のリポジトリを clone する（最初から main ブランチになる）
git clone https://github.com/<あなたのアカウント>/mirai-gikai-<地域>.git
cd mirai-gikai-<地域>
```

clone したら、**fork 直後の GitHub 設定**を済ませます
（`gh repo set-default`・Issues と Actions の有効化・`template` remote の登録）。
コマンドは [README の「リポジトリを用意する」手順4](../README.md#リポジトリを用意する) にあります。
特に `gh repo set-default` を忘れると、`gh pr create` が本家や配布元に PR を作ろうとします。

`.github/CODEOWNERS` の書き換えや Dependabot の有効化は、
調査（0-0）で着手が決まってから [セクション4](#4-github-設定とブランチの確認) で行います。

既に同じリポジトリの別ブランチで作業している場合は、worktree でも構いません
（同一ブランチは1つの worktree にしかチェックアウトできない点に注意）。

```bash
git worktree add ../mirai-gikai-<地域> -b <地域>/develop origin/main
```

続けて、権限設定と環境変数を引き継ぎ、依存をインストールします。

```bash
mkdir -p .claude && cp <既存の作業ディレクトリ>/.claude/settings.local.json .claude/
cp .env.example .env     # 値は セクション6 で設定
pnpm install --frozen-lockfile
```

> **調査（0-0）だけなら `.env` と `pnpm install` は不要です。**
> 議会サイトを読んで判定するだけなので、アプリを起動しません。
> 着手が決まってから揃えれば十分です。

## 0-0. その前に：その自治体で何が作れるか調べる

地方議会のサイトは自治体ごとに公開範囲も形式もまったく違います。
議案が件名しか公開されていない、議決結果が非公開、会議録が要旨だけ、といった差があり、
**fork しても主要機能が成立しない自治体があります。**

### 0-0-1. 呼び出し方

**この調査は、ユーザーへの確認や計画の提示より先に実行します。**

```
/council-survey <自治体名>
```

スキル一覧に `council-survey` が出ない場合（fork 元以外のリポジトリで作業しているとき等）は、
下記の SKILL.md を読み、**手順をそのまま実行してください。**
参照して自前の進め方を組み立てるのではなく、Step 1 から順に辿ります。

[.claude/skills/council-survey/SKILL.md](../.claude/skills/council-survey/SKILL.md)

このテンプレート以外のリポジトリで作業している場合は、
テンプレートの worktree またはクローンを探して同じパスを開きます。

```bash
# 手元のどこかにあるテンプレートのチェックアウトを探す
find ~ -maxdepth 4 -path "*/.claude/skills/council-survey/SKILL.md" 2>/dev/null
```

判定軸・Tier の定義・レポートテンプレートはすべて SKILL.md 側にあります。
**この手順書に書いてある Tier の要約は読み物であって、判定に使うものではありません。**

| Tier | 作れるもの |
|---|---|
| Tier 0 | 財政の可視化、議員名簿（**どの自治体でも作れる**） |
| Tier 1 | 議案一覧 |
| Tier 2 | 議案のAI解説 |

Tier とは別に、賛否の粒度（議員別/会派別/票数のみ/可否のみ/非公開）と
アーカイブの強さ（一般質問・委員会記録・記者会見）を評価します。詳細は SKILL.md。

## 0. 最初に読むもの：FORK_GUIDELINES

本リポジトリは AGPL-3.0 で公開されており、誰でも fork・改変・再配布できます。
ただし本家（team-mirai/mirai-gikai）は、商標保護と利用者の混乱防止のため
[FORK_GUIDELINES.md](../FORK_GUIDELINES.md) で**必須要件**を定めています。
これは AGPL-3.0 第7条 (c)(d)(e) に基づく追加条件であり、遵守は任意ではありません。

| FORK_GUIDELINES の必須要件 | 本テンプレートでの対応状況 |
|---|---|
| 1. サービス名称を「みらい議会＠地域名」形式に | `siteConfig.siteName` を変更する（セクション1-1） |
| 2. ロゴを独自のものに差し替え | プレースホルダー同梱。**必ず差し替える**（セクション5） |
| 3. トップ画像・OGP画像を差し替え | プレースホルダー同梱。**必ず差し替える**（セクション5） |
| 4. カラーテーマを変更 | プレースホルダー配色。**必ず変更する**（セクション1-4） |
| 5. 免責文言の表示 | `showTeamMiraiSection: false` のとき自動表示（対応済み） |
| 6. ソースコード公開先リンクの表示 | `siteConfig.sourceCodeUrl` を**必ず設定する**（セクション1-1） |

> [!WARNING]
> 本テンプレートに同梱されているロゴ・アイコン・OGP画像・配色は、本家の素材を使わないための
> **ニュートラルなプレースホルダー**です。そのまま公開すると、見た目が他の fork 版と区別できず、
> FORK_GUIDELINES の趣旨（利用者の混乱防止）を満たしません。必ず独自のものに差し替えてください。

### 0-1. AGPL-3.0 第13条（ソースコード公開）について

ネットワーク経由でサービスを提供する場合、利用者が**実際に稼働しているバージョン**の
ソースコードを入手できる手段を提供する必要があります。

- `web/src/config/site.config.ts` の `sourceCodeUrl` に、**自分の公開リポジトリ URL** を設定する
- 本家（https://github.com/team-mirai/mirai-gikai ）の URL では代用できない
- リポジトリは誰でもアクセスできる状態にする
- 設定するとフッターに「ソースコード（GitHub）」リンクが表示される。
  **空文字列のままだとリンクが出ず、ライセンス違反の状態になる**

### 0-2. 過去に指摘された典型的な不備

地方版の調査（[山田ゆうじ氏の記事](https://note.com/yujiyamada0512/n/n3d2eea5506fc)）では、
以下が複数の fork 版で問題として挙げられました。本テンプレートでは対処済みですが、
改変の際に再混入させないよう注意してください。

- 同意画面に「回答データは党内での政策検討に利用します」が残っている
- プライバシーポリシーに「政治資金規正法等に基づき7年間保管」「広告配信」が残っている
- 誤り報告ボタンが本家の Google フォームに飛ぶ
- 党への寄附リンクが残っている
- ソースコードへのリンクが本家を指している、または無い
- AIチャットが特定政党の紹介を行う

また、運営者が現職議員・会派・後援会名義である場合の**利益相反の開示**が求められています。
`siteConfig.operator.disclosure` に立場を記載すると、フッターの免責文言の下に表示されます。

## 1. 設定ファイルの変更

### 1-1. `web/src/config/site.config.ts` ← **最重要**

地域固有の情報はこのファイルに集約されています。`★` が付いた項目は必ず変更してください。

```typescript
export const siteConfig = {
  siteName: "みらい議会＠サンプル市",          // ★ 「みらい議会＠地域名」形式
  siteDescription: "サンプル市議会で今どんな議案が...",
  cityName: "サンプル市",                     // 自治体名（県の場合は "XX県"）
  councilName: "サンプル市議会",              // 議会名（県の場合は "XX県議会"）
  residentTerm: "市民",                       // 住民の呼称（県民・区民・町民 等）
  homeLayout: "bills" as "bills" | "archive", // "bills": 議案中心 / "archive": 議事録・活動中心
  executiveTitle: "市長",                     // 首長の役職名（知事・市長・区長・町長・村長）
  executiveName: "" as string,                // 首長の氏名（任意。空文字なら役職名のみ表示）
  governmentTerm: "市政",                     // 行政の呼称（県政・市政・区政・町政・村政）
  regularSessionMonths: [3, 6, 9, 12] as readonly number[], // 定例会の通常開催月（都道府県は [2, 6, 9, 12] 等）
  keywords: ["みらい議会＠サンプル市", "議案", ...],
  councilBaseUrl: "https://www.city.sample.lg.jp/",
  councilBillsDetailUrl: "https://www.city.sample.lg.jp/...", // 議案・議決結果一覧
  twitterHashtag: "みらい議会サンプル市",     // X のハッシュタグ（# なし）
  sourceCodeUrl: "https://github.com/YOU/YOUR_REPO", // ★ 自分の公開リポジトリ
  externalLinks: {
    report: "https://forms.gle/...",          // ★ 自前の誤り報告フォーム（空なら非表示）
    aboutNote: "",                            // サービス説明記事（空なら非表示）
    donation: "...",                          // showTeamMiraiSection=true のときのみ使用
    teamAbout: "...",                         // 同上
    terms: "...",                             // 同上
    privacy: "...",                           // 同上
    faq: "",                                  // ※現在参照されていない予約項目（/faq を使用）
  },
  managingParty: "",                          // 政党が運営主体でなければ空のまま
  operator: {
    name: "運営者名",                         // ★
    contactUrl: "https://...",                // ★ 問い合わせ先
    jurisdiction: "XX地方裁判所",             // ★ 利用規約の管轄裁判所
    disclosure: "",                           // 運営者の立場・利益相反の開示文
  },
  features: {
    // ★ `as const` のリテラル推論で false 指定時に型エラーになるのを防ぐため `as boolean` を残すこと
    bills: true as boolean,                   // 議案一覧・議案詳細（homeLayout: "bills" の場合は true 前提）
    showFactionStances: true as boolean,      // 会派別賛否（会派がない・可否のみの議会では false）
    generalQuestions: true as boolean,        // 一般質問・代表質問アーカイブ
    committeeMinutes: true as boolean,        // 委員会議事録アーカイブ
    pressConferences: true as boolean,        // 首長記者会見アーカイブ
    search: true as boolean,                  // 横断検索・テーマから探す（議案・一般質問・委員会が対象）
    aiChat: true as boolean,                  // AIチャット機能
    aiInterview: false as boolean,            // AIインタビュー機能（既定は無効）
    showTeamMiraiSection: false as boolean,   // 党公式として運営する場合のみ true
  },
} as const;
```

#### トップ構成（`homeLayout`）とパーツ選択のプレビュー

調査結果で議案の AI 解説が成立しない（Tier 1 等の）自治体では `homeLayout: "archive"` を選ぶと、議事録・活動中心のトップページに切り替わります（`homeLayout: "bills"` は `bills: true` が前提）。無効にしたパーツはナビ・検索・トップから自動的に非表示になり、首長記者会見や委員会が無い場合もトップのヒーロー右枠が自動でフォールバックします（議事録の原文は画面表示せず、要約・わかりやすい表現と公式会議録への出典リンクで案内します）。

ローカル環境で `cp .env.example .env` を済ませて `pnpm dev` を起動後、`http://localhost:3002/dev/top-preview` を開くと、DB 未起動でもブラウザ上で `bills` / `archive` や各パーツの ON/OFF を切り替えながら画面イメージを確認し、該当プロパティのスニペットをコピーできます。

#### `managingParty` と `showTeamMiraiSection` の効き方

この 2 つは「党の公式サービスかどうか」を切り替えるスイッチです。非公式運営（既定）では
以下が自動的に適用されます。

| 設定 | `false` / 空（非公式運営・既定） | `true` / 党名あり（党公式） |
|---|---|---|
| `showTeamMiraiSection` | フッターに免責文言を表示。党ロゴ・寄附リンク・党紹介セクションを非表示 | 党ロゴ・寄附リンク・党紹介セクションを表示 |
| `showTeamMiraiSection` | AIチャットのプロンプトに政党紹介を差し込まない | プロンプトに党概要・活動方針を差し込む |
| `managingParty` | 同意文言を「政策検討に活用します」等の汎用表現に | 「◯◯の政策検討に活用します」と党名入りに |
| `managingParty` | プライバシーポリシーから政治資金規正法・政策立案の記述を除外 | 政党向けの記述を表示 |

## 4. GitHub 設定とブランチの確認

このテンプレートは **`main`** を既定ブランチとして動いています。
**通常の fork では `main` のままそのまま開発・CI・PR が動く**ため、ブランチの作成や既定ブランチの変更、
ワークフロー内のブランチ名置換は不要です。

### 4-1. fork 直後の設定が済んでいるか確認する

[README の手順4](../README.md#リポジトリを用意する) を済ませていない場合は先にやります。

```bash
gh repo set-default --view          # 自分の fork（<あなたのアカウント>/mirai-gikai-<地域>）が出ること
git remote -v                       # origin が自分の fork、template が配布元であること
gh repo view --json hasIssuesEnabled
```

Actions は、fork のページの **Actions** タブにワークフロー一覧が出ていれば有効になっています
（`I understand my workflows...` のボタンが出ていたら押す）。

### 4-2. `.github/CODEOWNERS` と `supabase/config.toml` を書き換える

1. **`.github/CODEOWNERS`**: テンプレート配布元のアカウントが書かれたままになっています。
   自分（または運営チーム）の GitHub アカウントに置き換えてください。

   ```
   * @<あなたのアカウント>
   ```

2. **`supabase/config.toml` の `project_id`**: ローカル Supabase のコンテナ名・DB ボリュームの識別子です。
   そのまま起動すると、同じ PC 上の別地域版や本家とローカル DB が衝突・混在してしまいます。
   **`npx supabase start` を実行する前に**、必ず自地域固有の名前に変更してください。

   ```toml
   project_id = "mirai-gikai-<地域>"
   ```

   ※同じ PC で複数の地域版の Supabase を**同時に**起動する場合は、`supabase/config.toml` の各ポート番号（`54421` 等）と `.env` の `SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_URL` もずらしてください。

複数地域版を同じマシンで扱う場合は、あわせて `AGENTS.md`・`.claude/` 内の
worktree パス（`../mirai-gikai-local-worktree/`）を `../mirai-gikai-<地域>-worktree/` 等に
変更しておくと混ざりません（単一地域ならそのままでも動きます）。

### 4-3. ブランチ保護とレビュー体制を設定する（任意）

既定ブランチ（`main`）への直接 push を禁止し、PR 経由に統一する場合は
Settings → Branches でルールを追加します。

AI レビューに CodeRabbit を使う場合は、GitHub App を自分の fork にインストールします。
設定ファイル `.coderabbit.yml` は同梱済みです。
**fork 上の PR では自動レビューが走らないことがある**ため、その場合は PR に
`@coderabbitai review` とコメントして手動で起動します。

PR を作るときは、base が自分の fork の `main` になっているか確認します。
`gh` なら `--repo` と `--base` を明示すると確実です。

```bash
gh pr create --repo <あなたのアカウント>/mirai-gikai-<地域> --base main
```

### 4-4. デプロイを有効化する

テンプレートでは `deploy_web.yml` の push トリガーを無効化してあります。
デプロイする場合は、ワークフロー冒頭のコメントに従って以下を有効にします。

1. `on.push.branches` のコメントアウトを解除し、`main`（別ブランチ運用ならそのブランチ名）を指定
2. 必要であれば checkout の `ref:` を同じブランチ名に指定
3. `SUPABASE_*` と `WEB_VERCEL_DEPLOY_HOOK_URL` のシークレットを登録

詳細は [本番環境方針検討](20260219_1100_本番環境方針検討.md) を参照してください。

### 4-5. テンプレートの更新を取り込む

fork した時点のコピーは自分の fork に入っていますが、**その後の配布元の更新は自動では
流れてきません。** 配布元をリモートとして登録しておきます
（README の手順4 で既に登録済みなら不要）。

```bash
git remote add template https://github.com/bakumon-mirai/local-mirai-gikai.git
git fetch template main
```

取り込み方は2通りです。

| 方法 | 向いている場面 |
|---|---|
| `git merge template/main` | テンプレートの変更をまとめて取り込む。地域固有の変更と競合しやすい |
| `git cherry-pick <コミット>` | 必要な修正だけ選んで取り込む。**地域版では通常こちらが現実的** |

地域版は `site.config.ts`・画像・シードデータを大きく書き換えているため、
merge すると毎回その部分が競合します。cherry-pick で必要なものだけ拾うほうが楽です。

### 4-6. 脆弱性の自動通知（Dependabot）を有効にする

ライブラリに脆弱性が見つかったとき、修正版に上げる PR が自動で届くようにします。
fork では初期状態でオフのことがあるため、有効にしてください
（脆弱性の PR は既定ブランチ向けに届きます）。

```bash
gh api -X PUT repos/<あなたのアカウント>/mirai-gikai-<地域>/vulnerability-alerts
gh api -X PUT repos/<あなたのアカウント>/mirai-gikai-<地域>/automated-security-fixes
gh api repos/<あなたのアカウント>/mirai-gikai-<地域> --jq '.security_and_analysis'
```

Web UI なら Settings → Code security で Dependency graph・Dependabot alerts・Dependabot security updates を Enable にします。
届いた PR の扱い方は [依存関係の脆弱性対応手順](20261122_1000_依存関係の脆弱性対応手順.md) を参照してください。
AI エージェントには「Dependabot の PR を対応して」と頼めば、仕分けと確認を行います。

### 4-7. 既存の別用途 fork にテンプレートを足した場合（該当者のみ）

すでに別の `mirai-gikai` 系 fork を持っていて、そこに `template/main` から `<地域>/develop` ブランチを追加した場合（README の NOTE / AI セットアップ指示書 7B）は、
**既存の既定ブランチには触れず**、以下のファイル内のベースブランチ参照（`main`）だけ `<地域>/develop` に置き換えてください。

| ファイル | 内容 |
|---|---|
| `.github/workflows/code_check.yml` | `branches: [main]` → `[<地域>/develop]` |
| `.github/workflows/integration_test.yml` | `branches: [main]` → `[<地域>/develop]` |
| `.github/workflows/deploy_web.yml` | 有効化する場合は対象ブランチを `<地域>/develop` に |
| `AGENTS.md` | ベースブランチの指定（`main` → `<地域>/develop`） |
| `.claude/agents/worktree-worker.md` | ブランチ作成の基点、PR のベース |
| `.claude/skills/parallel-pr/SKILL.md` | 同上 |

## 9. クロスプラットフォーム対応（Windows / Mac）

### 9-1. devスクリプトのポート指定

`web/package.json` と `admin/package.json` の dev スクリプトは、Bash の `${VAR:-default}` 構文ではなく
Node.js の `process.env` 経由でポートを読み取る方式です。Windows でも動作するため変更不要です。

### 9-2. Claude CLI（AI情報収集機能）の Windows 対応

`admin/src/features/ai-collection/server/utils/execute-claude.ts` に Windows 対応が組み込まれています。
`CLAUDE_CLI_PATH` 環境変数にフルパスを設定するか、`npm install -g @anthropic-ai/claude-code` を行ってください。

### 9-3. Supabase CLI

`npx supabase start` は Docker を使用します。Windows の場合は WSL2 + Docker Desktop が必要です。

### 9-4. 改行コード

Biome が LF を強制するため、Windows では `git config core.autocrlf input` を推奨します。
